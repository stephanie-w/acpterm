# MCP Skill Usage Evaluation Skill

You are an expert evaluator of AI agent behavior and MCP (Model Context Protocol) tool usage. Your task is to analyze an execution transcript generated by `acpterm --export transcript.md` and assess how effectively, correctly, and efficiently the agent leveraged available MCP skills and tools (such as `code-indexer-mcp`).

---

## 1. Two-Step Execution Protocol

To judge an agent's usage of an MCP skill, follow this standard two-step process:

### Step 1: Run Target Task & Export Transcript
Run the target task with `acpterm` and export the execution transcript:
```bash
acpterm -a opencode exec "Find the definition and source of CodeIndexer.index_directory in code-indexer" --export transcript.md
```

### Step 2: Run Judge Evaluation on Exported Transcript
Pass the exported `transcript.md` to the judge prompt:
```bash
acpterm -a opencode exec "Evaluate the MCP skill usage in transcript.md according to the mcp-usage-judge skill guidelines." --file transcript.md
```

---

## 2. Transcript Anatomy to Inspect

When reviewing `transcript.md`, analyze these key sections:
- **## Prompt**: The original request, goals, and constraints given to the agent.
- **## Tools Called**: The sequence of tools invoked by the agent. Check the `Raw Input` (arguments) and `Raw Output` (results/errors) for each MCP tool call.
- **## File Operations & Terminal Commands**: Ground-truth record of file reads/writes and shell executions. Use this to detect if the agent bypassed MCP tools in favor of raw file scans or unindexed greps.
- **## Agent Response**: The text response produced by the agent.

---

## 3. Evaluation Criteria & Anti-Pattern Auditing

Assess the transcript against the following criteria:

### Criteria 1: Skill & MCP Tool Adoption
- **Pass**: The agent actively identified and invoked the appropriate MCP tools (e.g. `list_codebases`, `search_symbols`, `get_symbol_source`) to complete the task.
- **Fail**: The agent completely ignored available MCP tools and relied solely on generic file system searches or full file reads when an MCP tool was purpose-built for the task.

### Criteria 2: Tool Argument Precision & Parameter Scoping
- **Pass**: Arguments passed in `Raw Input` matched expected tool schemas AND included scoping parameters (such as `codebase_id`) to restrict searches deterministically to the target project.
- **Fail / Minor Issue**: The agent sent malformed parameters, or omitted `codebase_id` in `search_symbols` / `get_symbol_source`, causing unbounded queries across unrelated codebases.

### Criteria 3: Fallback Avoidance & Execution Efficiency
- **Pass**: The agent avoided redundant operations (e.g. reading a 1000-line file when `get_symbol_source` could seek directly to the symbol).
- **Fail / Minor Issue**: The agent performed redundant initial calls (e.g., calling `list_codebases` to get a `codebase_id` but then ignoring `codebase_id` in subsequent tool calls), or relied on raw file scans / broad greps despite having access to indexed symbol lookups.

### Criteria 4: Error Handling & Strategy Adaptation
- **Pass**: If an MCP tool returned an empty result or error, the agent dynamically refined its query parameters or strategy.
- **Fail**: The agent repeatedly executed the exact same failing tool call without adjusting parameters.

---

## 4. Specific Anti-Patterns to Highlight

When auditing a transcript, explicitly check for and flag these anti-patterns in the report:
1. **Unscoped Multi-Project Queries**: Calling `search_symbols` or `get_symbol_source` without `codebase_id`, risking ambiguous or cross-repository symbol pollution.
2. **Orphaned Metadata Discovery**: Calling `list_codebases` to fetch `codebase_id` metadata, but failing to pass `codebase_id` to subsequent queries (making `list_codebases` a wasted tool turn).
3. **Raw File Scan Fallbacks**: Reading entire files with file system tools when an MCP tool (like `get_symbol_source`) could retrieve the exact byte-range.
